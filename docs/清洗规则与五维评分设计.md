# 清洗规则表与五维评分公式

依据：`数据探查报告.txt`（由 `explore_data.py` 对当前注入异常后的 ml-1m 实测得出）。

## 0. 清洗动作分类（贯穿全文的定义）

| 动作 | 含义 | 数据是否保留 |
| --- | --- | --- |
| **修复 (repair)** | 存在唯一、无歧义的还原方式，可直接改写字段 | 保留（修改后） |
| **去重 (dedup)** | 同一业务实体的多余副本，按保留策略取一条 | 保留一条，删除副本 |
| **隔离 (isolate)** | 无法可靠还原的错误记录，移入隔离区文件，不进入清洗后数据集 | 不保留在主数据中 |
| **登记 (log)** | 保留数据但标记为缺失/待定，计入"未解决问题" | 保留并标记 |

隔离的记录写入 `isolate/` 目录（按文件和规则编号分文件），并保留隔离原因。**隔离≠修复**，前端和 Agent 报告必须区分表述。

### 1.5 时间边界 T1/T2

评分时间实际范围：2000-04-25 ~ 2003-02（清洗后复核）。

- **T1 = 2002-01-01 00:00:00 UTC**（训练期截止）
- **T2 = 2002-07-01 00:00:00 UTC**（验证期截止）
- 训练集：ts ≤ T1；验证集：T1 < ts ≤ T2；测试集：ts > T2

三段比例在清洗完成后统计并写入报告；此边界登记为数据版本的一部分，后续迭代不得更改。

## 2. 五维评分公式

### 2.1 总体口径

- 每维得分域 **0–100**，对三张表分别计算，再合成数据集总分。
- 合成方式：`总分 = (ratings 分 × 0.6 + users 分 × 0.2 + movies 分 × 0.2)`。
  依据：ratings 是本系统的核心业务数据（1M 条），movies/users 作为维表规模小但影响关联正确性，故给 0.2。
- **清洗前后用完全相同的计算 Job 与参数**，只有输入数据版本不同，保证可比。
- users/movies 的 **Up-to-date 标注为"不适用"**（静态快照、无时间字段），不计入该表综合分，前端明确标注"无法评价"；ratings 的总分按其余四维均值归一。下面 ratings 的 Ud 定义见 2.2。

### 2.2 ratings.dat 各维公式（N = 记录总数）

记号：通过某条件的记录数记为 `n(条件)`。

| 维度 | 公式 | 设计依据 |
| --- | --- | --- |
| **Accurate 准确性** | `100 × n(1≤rating≤5 为整数 ∧ 时间戳在 1990–2003 内 ∧ UserID、MovieID 存在于主表) / N` | "值真实反映现实"在自动评价下退化为：值落在合法值域且外键可解析。 |
| **Complete 完整性** | `100 × n(4 个字段均非空) / (N × 4) × 4`，即非空字段占比 | 以必填字段无空值为准；字段级而非记录级，可反映部分缺失。 |
| **Unique 唯一性** | `100 × (1 − Σ_{(u,m)} max(0, cnt(u,m)−1) / N)` | 冗余率：同一业务事件的多余副本占比。 |
| **Up-to-date 时效性** | `100 × n(时间戳可解析且落在数据集声明年代 1990–2003) / N` | 历史静态数据集无法要求"新"，以**时间可解释性**为代理指标；并在报告说明：真正的时效性应以业务参照点（数据集发布 2003-02）讨论，本指标只衡量"时间信息可用且未失真"。 |
| **Consistent 一致性** | `100 × n(字段数=4 ∧ rating 为整数字符串 ∧ 时间戳为 10 位秒级数字 ∧ ID 为数字) / N` | 格式与单位统一：分隔符、字段数、时间单位（秒）、值域表示一致。 |

> Accurate 与 Consistent 有重叠但侧重不同：Consistent 只看**格式**（不看值域和外键），Accurate 看**值域与引用**。探查数据下两者数值接近（错误是按行注入的），若清洗时出现大量"格式正确但值越界"的记录，二者会分离，这正是设计两维的意义。

### 2.3 users.dat（N = 用户记录数）

| 维度 | 公式 |
| --- | --- |
| Accurate | `100 × n(gender∈{F,M} ∧ age∈7 档 ∧ occ∈0–20 ∧ zip 为 5 位数字) / N` |
| Complete | `100 × (5 字段非空总数) / (N × 5)` |
| Unique | `100 × (1 − Σ_id max(0, cnt(id)−1) / N)` |
| Consistent | `100 × n(字段数=5 ∧ 各字段符合规范格式) / N` |
| Up-to-date | **不适用**（用户属性为 2000 年自填快照，无任何时间字段可验证"当前状态"；无法验证的情况如实标注） |

局限（报告必须写明）：格式正确 ≠ 内容真实，GroupLens 未核验自填属性，Accurate 实际是"**域合规率**"。

### 2.4 movies.dat（N = 电影行数，按 (title, year) 去重前）

| 维度 | 公式 |
| --- | --- |
| Accurate | `100 × n(年份可解析且 ≤2003 ∧ 全部类型 ∈ 18 词表 ∧ 标题非空) / N` |
| Complete | `100 × (标题、类型非空总数) / (N × 2)` |
| Unique | `100 × (1 − Σ_{(title,year)} max(0, cnt−1) / N)`（同时覆盖同 ID 重复与跨 ID 同名重复） |
| Consistent | `100 × n(字段数=3 ∧ 标题以 (yyyy) 结尾 ∧ 类型为词表内 \| 分隔 ∧ ID 为数字) / N` |
| Up-to-date | **不适用**（电影属性静态；年份"新旧"不等于数据"过时"） |

局限：同名同年但确为两部电影的情况（翻拍、同名）无法仅凭标题判断；`Misérables, Les (1995/1998)` 这类不同年份同名会保留两条，是正确行为。

### 2.5 无法验证 / 评价局限清单（写入评估报告模板）

1. 用户属性、电影元数据的**真实性**不可自动验证（Accurate 只是域合规 + 引用完整）。
2. users/movies 的时效性不可评价（静态快照）。
3. 置 NULL 的字段（性别 X、非法邮编等）仍留在数据集中，Complete 的提升依赖隔离/置空的权衡，报告中要写明"登记≠修复"。
4. 隔离记录使分母变小，后评分提高部分来自"删除劣质记录"而非"修复"，Agent 解释时必须说明数据量变化。
5. 时间参照只覆盖 1990–2003；清洗阶段确定的时间边界 T1/T2 不参与打分，只用于后续迭代切分。

## 3. Hadoop 实现要点

- 每条规则 = 一个 Mapper 侧判定 + 标记输出（多路输出：clean / isolate-规则号），Reducer 侧做去重类规则（R7、U6、M5）与计数。
- 评分 Job：一次扫描输出五维各计数器（`n(条件)` 与 N），最后汇总公式计算；同一 Job 分别跑原始版本与清洗后版本。
- 输出登记：`dataset_version`、`rule_version`（本文件规则表的版本号）、`task_id`、T1/T2 与各维明细计数，供 Agent 工具接口直接返回。
