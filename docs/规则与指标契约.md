# 规则与指标契约

系统使用 `rules-v2.0` 和 `metrics-v2.1`。历史报告、历史定义与历史候选产物按原版本保留，不原地重写。

## 明确口径

- 声明年代固定为 1990-01-01 00:00:00 UTC 至 2003-03-15 23:59:59 UTC，对应秒数 631152000～1047772799；`metrics-v2.0` 的上界不作为正式口径。T1/T2 保持 1009843200、1025481600，不变。
- 完整性按必需字段计数，空白及去除首尾空白后的 `NULL` 为缺失。users/ratings 最多计五/四字段；movies 计标题和类型。不可适用指标保存 null，空表的适用指标为 0。
- 年份不可解析的电影和非法业务键按源记录独立计数，不以字符串 hash 近似唯一性。电影标题业务键采用去除末尾年份、trim、转小写后的标题和年份；与第二阶段去重的分组方式一致。
- 原始输入保持 Latin-1 字节，计算输出为 UTF-8。编码转换记录在版本与文件清单中；不把每条合法电影都说成发生了内容修复。
- 正常保留为 `keep`，确定性改写为 `repair`，保留缺失/待定问题为 `log`，移出主表为 `isolate` 或 `dedup`。记录可以先修复再登记或隔离，动作链逐步保存，不被最后命中的规则覆盖。评分非整数用 R2，整数越界用 R3。

## 保留策略与边界

继续按当前实际管线执行 U/M/R 清洗，原始评分使用原始参照集合，清洗后评分使用最终参照集合。用户 ID 重复按合法字段数选择；电影 ID/标题重复按合法字段数选择；评分重复保留最新时间戳。并列按源文件相对路径及原始字节偏移选择，保证多输入文件下确定性。

当前同名电影归并并未按“有评分记录的 ID 优先”执行；电影表也没有实现设计中的 M6 ID 归并和 M2 缺失标题补全。系统显式保留实际执行口径，并将这些差异列入报告局限，不靠报告声称未执行的业务规则已经实现。后续若引入这些业务策略，另立规则版本并重新验收。

## 来源与证据协议

源记录身份为 SHA-256：输入版本、源表、源文件相对路径和原始字节偏移，以零字节分隔后编码为 UTF-8。单一偏移不能区分多个文件。原始字节与完整文件校验值保留在 Raw 版本中。

中间记录继续使用四段 envelope，首段为 `offset@base64url(origin_json)`，旧四段记录仅供兼容读取。origin 保存源身份、原始记录、事件链及合并来源关系。电影第二次去重必须继承它；中间文件偏移不能成为新的原始来源。

事件链中的每一步保存 rule、action、before、after。去重事件还指向胜出来源。正式 Evidence 由这些实际计算事件生成；没有来源标识或事件链的历史样例不能补造为正式证据。记录最终去向与动作次数分别统计，每条原始记录只计一次最终去向。

结构化输出要求：字符串邮编保留前导零；真实缺失使用 null；电影类型为完整字符串数组；时间戳为 UTC 秒整数。已登记 Rule/Metric 定义不可原地改写，实际 jar、源代码、执行配置和镜像身份另行固定。
