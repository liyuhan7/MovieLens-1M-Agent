## 2. 清洗动作定义

| 动作 | 含义 | 数据去向 |
| --- | --- | --- |
| 修复 repair | 存在唯一、无歧义的还原方式 | 改写后保留在清洗后数据 |
| 去重 dedup | 同一业务实体的冗余副本 | 保留一条(策略见各规则),副本移入隔离区并登记 |
| 隔离 isolate | 无法可靠还原的错误记录 | 移入隔离区,不进入清洗后数据 |
| 登记 log | 保留数据但标记缺失/待定 | 保留在清洗后数据,计入"未解决问题" |

**隔离 ≠ 修复**。前端与 Agent 解释必须区分;隔离导致的分数上升是"删除劣质记录"而非"修复",报告须说明数据量变化。

## 3. 清洗规则表(rules-v1.0)

判定顺序:行级规则(Map 阶段,自上而下短路)→ 分组规则(Reduce 阶段)。

### 3.1 ratings.dat

| 编号 | 检测条件 | 动作 | 依据 |
| --- | --- | --- | --- |
| R1b | 整行按 `,` 拆分恰为 4 个合法字段(如 `25,688,4,978133460`) | **修复**:`,`→`::` | 分隔符损坏,字段语义完整可无歧义还原 |
| R1a | 字段数=5 且前 4 字段合法(尾部 EXTRA_FIELD) | **修复**:截断为 4 字段 | 尾部注入,前 4 字段自洽 |
| R1c | 字段数≠4(经 R1a/R1b 修复后仍异常)或必填字段为空 | **隔离** | 缺失内容不可还原 |
| R2 | 评分非整数(`3.5`、`five`) | **隔离** | 四舍五入或词义映射属于编造数据 |
| R3 | 评分 ∉ {1..5}(`0`、`6`) | **隔离** | 越界值无还原依据 |
| R4 | 时间戳非数字(`-1`) | **隔离** | 无法参与 T1/T2 划分 |
| R5 | 时间戳数值 > 10^12(毫秒级) | **修复**:÷1000 转秒 | 毫秒→秒是无歧义单位换算 |
| R6 | 时间戳(经 R5 修复后)不在 [1990-01-01, 2003-03-15] UTC | **隔离** | 超出数据集声明覆盖年代,不可解释 |
| R8a | UserID ≥ 1,000,000 且减 1,000,000(或 2,000,000)后存在于清洗后用户表 | **修复**:减偏移 | 偏移注入可精确还原 |
| R8b | MovieID ≥ 1,000,000 且减偏移后存在于清洗后电影表 | **修复**:减偏移 | 同上 |
| R9 | 经 R8 修复后 UserID/MovieID 仍不存在于清洗后主表 | **隔离** | 悬空引用 |
| R7 | 同一 (UserID, MovieID) 多条(R1–R9 后仍存留的行) | **去重**:保留时间戳最大的一条;并列取文件序靠前 | 用户对电影的最新评价为准,与官方"每用户每电影一条"口径一致 |

### 3.2 movies.dat

| 编号 | 检测条件 | 动作 | 依据 |
| --- | --- | --- | --- |
| M7 | 全文件 ISO-8859-1 读入 | **修复**:输出统一 UTF-8 | 编码归一(ISO-8859-1 解码在 Mapper 内完成) |
| M8 | 标题含 UTF-8→Latin-1 双重编码乱码(如 `LÃ©on`),且逆转可还原(不含 U+FFFD) | **修复**:`bytes(latin1).decode(utf8)` 逆转 | 双重编码是确定性可逆变换 |
| M1 | 标题首尾空白 | **修复**:trim | 无歧义 |
| M2 | MovieID 缺失/非数字,或标题字段为空(经 M1 后) | **隔离** | 无主键或空标题不可还原 |
| M3 | 标题不以 `(yyyy)` 结尾或年份不可解析/越界(如 `[20XX]`) | **登记**:保留原文本,年份视为缺失 | 标题文本本身可能是真实片名,不可臆造年份 |
| M4 | 类型含词表外类型(`UnknownGenre`) | **修复**:剥离非法类型词并登记;若剥离后为空则置 NULL **登记** | 词表外类型无语义;剥离不引入新信息 |
| M5a | 同一 MovieID 多行 | **去重**:保留"合法字段数最多"的行;并列取文件序靠前;登记冲突 | 无法判定真伪,保守取信息最全者 |
| M5b | 跨 MovieID 同名同年(标题去年份空白后归一,不含年份者按行独立不分组) | **去重**:同 M5a 策略保留一条,其余**隔离** | 官方声明存在因重复录入导致的同内容多 ID;保留策略与 M5a 一致以保持确定性。其副作用在 §4.4 如实声明 |

### 3.3 users.dat

| 编号 | 检测条件 | 动作 | 依据 |
| --- | --- | --- | --- |
| U1a | 字段数=6 且前 5 合法 | **修复**:截断为 5 字段 | 尾部注入 |
| U1c | 单字段冒号分隔行,按 `:` 拆分恰为 5 个非空字段(如 `3036:M:56:13:14843`) | **修复**:`:`→`::` | 分隔符损坏,五字段语义完整无歧义 |
| U1b | UserID 缺失/非数字,或字段数<5 | **隔离** | 无主键不可还原;其余字段缺失不隔离(见 U2-U5) |
| U2 | 性别 ∉ {F,M}(`X`) | **登记**:置 NULL | 隔离整行会连带丢失该用户全部评分,代价不成比例 |
| U3 | 年龄段 ∉ {1,18,25,35,45,50,56} | **登记**:置 NULL | 同上 |
| U4 | 职业 ∉ 0..20 | **登记**:置 NULL | 同上 |
| U5a | 邮编 ZIP+4(`99999-9999`) | **修复**:取前 5 位 | 标准 ZIP 语义 |
| U5b | 邮编 9 位数字 | **修复**:取前 5 位 | 同上 |
| U5c | 邮编其他非法(`12`、`ABCDE`、6-8 位、空) | **登记**:置 NULL | 补零/猜测属于编造 |
| U6 | 同一 UserID 多行 | **去重**:保留"合法字段数最多"的行;并列取文件序靠前;登记冲突 | 不做字段级合并(避免拼装出新记录) |

### 3.4 编排顺序与处置日志

```
extractUsers/extractMovies(原始表) ──参照 ID──┐
scoreRatings/scoreUsers/scoreMovies(原始) ┐  │
cleanUsers(U1–U6) ──────────clean IDs ────┤  ├→ cleanRatings(R1–R9)
cleanMovies(M7,M8,M1–M4,M5a) ──清理行──┐  │  │
      └→ cleanMoviesTitle(M5b) ──clean IDs ──┘  └→ 清洗后评分(score 三表)
原始三表 ─────────────────────────────────────────→ 清洗前评分(score 三表)
```

所有修复/去重/隔离均随输出产生处置记录(`seq|action|rule|payload`),聚合为报告的
`disposition` 段,供 Agent 解释与前端展示。

## 4. 五维评分方案

### 4.1 总体口径

- 每维 **0–100 分**,按表分别计算;数据集综合分 = `ratings×0.6 + users×0.2 + movies×0.2`(权重为已登记默认配置;管线向 Agent 预留 `rule_pack` 档位参数,当前仅 `default`)。
- 权重依据:ratings 是核心业务数据(100 万行);users/movies 为维表,规模小但决定关联正确性。
- **清洗前后使用同一个评分作业 jar、同一套常量与参数,仅输入数据版本不同**,保证口径可比(代码级保证)。
- 评分只做计数,公式计算在编排层完成;**所有计数必须来自 Hadoop 作业输出**。
- users/movies 的 **Up-to-date 标记"不适用"**:静态快照无时间字段,前端明确标注"无法评价",该表综合分按其余四维均值。

### 4.2 评分常量(与清洗共用,写死在共享常量)

- 合法评分值域:整数 1–5
- 时间戳合理范围:[1990-01-01 00:00:00, 2003-03-15 23:59:59] UTC(数据集 2003-02 发布)
- 合法年龄段:{1,18,25,35,45,50,56};合法职业:0–20;合法性别:{F,M}
- 合法类型词表:18 个官方类型
- 时间边界(供切分,不参与打分):**T1 = 2002-01-01 00:00:00 UTC,T2 = 2002-07-01 00:00:00 UTC**(训练 ≤T1,验证 (T1,T2],测试 >T2;比例在清洗后实测写入报告,此边界登记后不得更改)

### 4.3 各表公式

记号:N=表总行数(原始行数,不因评分而过滤);n(条件)=满足条件的行数/字段数。

**ratings.dat**

| 维度 | 公式 |
| --- | --- |
| Accurate | `100 × n(4字段 ∧ rating∈1..5 ∧ ts∈合理年代 ∧ UserID∈参照用户集 ∧ MovieID∈参照电影集) / N` |
| Complete | `100 × 前4字段非空总数 / (N×4)` |
| Unique | `100 × (1 − Σ_(u,m) max(0, cnt(u,m)−1) / N)`(非法行按整行哈希独立计入分母) |
| Up-to-date | `100 × n(ts 可解析且∈合理年代) / N` |
| Consistent | `100 × n(4字段 ∧ rating 匹配 ^[1-5]$ ∧ ts 为 9 或 10 位秒级数字 ∧ uid/mid 匹配 ^\d+$) / N` |

参照集口径:评原始数据用**原始表**提取的 ID 集合;评清洗后数据用**清洗后表**的 ID 集合(由 extract 作业生成,评分作业经 distributed cache 读取)。

**users.dat**

| 维度 | 公式 |
| --- | --- |
| Accurate | `100 × n(gender∈{F,M} ∧ age∈7档 ∧ occ∈0..20 ∧ zip ^\d{5}$) / N` |
| Complete | `100 × 5字段非空总数 / (N×5)` |
| Unique | `100 × (1 − Σ_id max(0, cnt(id)−1) / N)` |
| Consistent | `100 × n(5字段 ∧ uid ^\d+$ ∧ gender [FM] ∧ age∈7档 ∧ occ ^\d+$ ∧ zip ^\d{5}(-\d{4})?$) / N` |
| Up-to-date | 不适用 |

注:Consistent 允许 ZIP+4(格式规范),Accurate 要求 5 位纯数字(值标准化)——两者分层,不是笔误。

**movies.dat**

| 维度 | 公式 |
| --- | --- |
| Accurate | `100 × n(3字段 ∧ 标题非空 ∧ 年份可解析且≤2003 ∧ 类型全部∈词表) / N` |
| Complete | `100 × 非空(标题,类型)字段总数 / (N×2)` |
| Unique | `100 × (1 − Σ_(title,year) max(0, cnt−1) / N)`,title 归一=去年份首尾空白;M5b 清洗后该键无超额 |
| Consistent | `100 × n(3字段 ∧ mid ^\d+$ ∧ 标题以 (yyyy) 结尾 ∧ 类型为词表内竖线分隔) / N` |
| Up-to-date | 不适用 |

### 4.4 无法验证与评价局限(报告必须原样呈现)

1. **真实性不可自动验证**:Accurate 实为"值域合规 + 引用可解析";用户自填属性 GroupLens 未核验。
2. users/movies 时效性不可评价(静态快照)。
3. 置 NULL 字段(U2–U5c)留在数据中,登记≠修复;Complete 的提升受此限制(对应 users 表 Accurate/Consistent 稳定在 99.75 而非 100)。
4. 隔离使分母变小,部分分数上升来自"删除劣质记录",须结合数据量变化解释。
5. 时间参照只覆盖 1990–2003;T1/T2 只用于切分,不参与打分。
6. `Movie with malformed year [20XX]` 类测试标题:M3 保留登记、(title, 缺年份) 组不参与 M5b 去重,是"未解决问题"的真实保留,不是遗漏。
7. M5b 按 (title,year) 归并保留一条副本后,指向被归并 ID 的既有评分按 R9 悬空引用隔离——有效评分行数因此少于"不去重"口径;若业务优先保留评分量,后续版本可改为 ID 重映射(改规则须升版本并登记)。

## 5. Hadoop 作业架构

运行环境:Docker 容器 `movielens-hadoop:3.3.6`(OpenJDK 11 + Hadoop 3.3.6),`mapreduce.framework.name=local`,输入输出经卷挂载。**如实口径:单容器 local 模式 MapReduce,真实 MR 管线(map/shuffle/reduce),非分布式集群。**

### 5.1 作业清单(单 jar `iter1.jar`,按作业名分发)

| 作业 | 输入 | 输出 | 实现规则 |
| --- | --- | --- | --- |
| extractUsers / extractMovies | 原始/清洗后 users 或 movies | `ids.txt` | 参照 ID 集合 |
| scoreRatings | ratings + cache(参照 ID) | 指标计数(N/ACC/COMP/UD/CONS/TRAIN/VALID/TEST/UNIQ_EXCESS) | 4.3 ratings 公式 |
| scoreUsers | users | 同上(无 UD) | 4.3 users 公式 |
| scoreMovies | movies | 同上(无 UD) | 4.3 movies 公式 |
| cleanUsers | users | clean / isolate / log 流 | U1(含 U1c)–U6 |
| cleanMovies | movies | 同上 | M7,M8,M1–M4,M5a |
| cleanMoviesTitle | cleanMovies 的 clean 行 | 同上 | M5b(标题级二次去重) |
| cleanRatings | ratings + cache(清洗后 users/movies ID) | 同上 + TRAIN/VALID/TEST 计数 | R1–R9 |

### 5.2 关键实现决策

- **输入编码**:Mapper 内以 ISO-8859-1 解码原始行,输出统一 UTF-8(M7 在管线内完成,而非预处理)。
- **行序稳定性**:以文件字节偏移为 seq,去重规则"并列取文件序靠前"有确定性依据。
- **行级判定在 Mapper、去重在 Reducer**:R7 按 (uid,mid)、U6 按 UserID、M5a 按 MovieID、M5b 按 (titleNorm,year) 分组;ISO 组直通隔离区。
- **处置输出**:每行输出 `seq|action|rule|payload` 统一构型,编排层聚合为各规则计数与样例。
- **参照广播**:清洗后 users/movies ID 列表经 `-files` + DistributedCache 广播给 cleanRatings / scoreRatings(判定与对照引用)。
- **同一 jar 评两侧**:score 类作业对原始与清洗后数据的差别仅在输入路径与 cache 参照文件。

### 5.3 输出目录契约

```
ml-1m/outputs/
├── <tag>/report.json   # 每次任务的评估报告(报告是唯一对外数据面)
├── registry.json       # 版本登记(追加式)
├── agent_memory.db     # Agent 会话(SQLiteSession)
├── traces/*.json       # Agent 推理链(本地 trace)
└── _tmp_*              # 中间产物(clean/score 作业输出,可人工抽验,可删)
```

```json

  "created_at": "<ISO8601>",

  "t1": "2002-01-01T00:00:00Z",
```

## 7. Agent 架构(真实 LLM Agent)

### 7.1 设计定位

Agent = LLM 循环(OpenAI Agents SDK + DeepSeek)+ 工具调用 + 证据约束下的解释生成。
**全部数字必须来自工具返回的报告实测字段;禁止编造;查询对象尚未生成时如实说明,不得占位。**

```
用户自然语言
  → LLM(deepseek)循环,自主决定调用工具
    ├─ run_clean_data_pipeline(rule_pack) → run_pipeline.py → docker run → hadoop jar(真实 MR)
    └─ read_latest_report / read_report_field / read_registry / read_samples(纯读,零 Hadoop)
  → 组织回答:任务状态、五维对比、数据量变化、处置区分(修复/去重/隔离)、
     清洗后数据版本、规则版本、T1/T2、评估报告路径与局限
```

### 7.2 模型与鲁棒性

- 模型:`deepseek-chat`(可经环境变量切换 DeepSeek 其他型号),经 SDK 内置路径接入
  (`AsyncOpenAI(base_url="https://api.deepseek.com")` + `OpenAIChatCompletionsModel`)。
- 每次 Agent 构建新建模型客户端(httpx 连接池绑定 asyncio loop,禁止跨线程复用全局客户端)。
- 模型调用超时 120s/次;429/5xx 经指数退避自动重试 2 次;**工具执行失败不重试**,错误如实上报。
- 未配置 key 时服务启动正常,`POST /api/tasks` 返回 503 并明示"模型未配置",不降级到模板问答。

### 7.3 工具表

| 工具 | 输入 | 输出 | 副作用 |
| --- | --- | --- | --- |
| `run_clean_data_pipeline` | rule_pack(默认 default=rules-v1.0) | 立即返回 task_id/排队提示;最终结果经第二阶段总结落状态 | 触发全管线(约 3 分钟) |
| `read_latest_report` | 无 | 最新成功报告全文 | 无 |
| `read_report_field` | tag, section | 报告单段:scores/dataset_composite/row_change/disposition/split/limitations/metrics_* | 无 |
| `read_registry` | 无 | 版本登记(输入/输出数据版本、规则版本、T1/T2、切分计数) | 无 |
| `read_samples` | tag, kind(clean/isolate/log) | 三表样例 | 无 |

### 7.4 结构强制与防编造

- **重跑门槛(结构强制)**:常驻工具仅只读组;`run_clean_data_pipeline` 仅当用户原话命中
  "重新/重跑/清洗/清理/再跑"类触发词时注入本轮,其余场景模型无权发起管线。
- **只读优先**:数据未变(输入指纹一致)时应复用最新报告,Agent 需先调 `read_registry`/`read_latest_report` 比对。
- **Prompt 三条硬约束**:① 一切分数/计数/版本必须来自工具返回字段;② 措辞区分修复(repair)/去重(dedup)/隔离(isolate),删除不得说成修复,并必引局限;③ 所求数据未生成时如实说明,不得占位。
- **回复校验**:回复中的分数类数值须经报告实测值白名单校验(±0.01),越界值在 API 响应 `flagged` 中列出并附"该数字未出自本次报告"标记。
- **失败语义**:任何阶段失败 → 任务 failed + 失败环节与原因;管线失败时由 Agent 如实转述,不生成部分占位报告。

### 7.5 任务生命周期与会话

- **长任务两阶段**:Agent 触发管线后立即回执(task_id + 阶段叙事),任务状态经
  `pipeline-starting → pipeline-executing → agent-summarizing → done` 推进;管线完成后 Agent 追加
  一轮总结作为最终回答。追问走同一会话(同步返回,秒级)。
- **会话记忆**:SQLiteSession 落盘 `outputs/agent_memory.db`,按 task_id;服务重启后同任务
  追问仍携带历史上下文。
- **并发控制**:全局锁串行(管线共享 `_tmp_*` 中间目录),第二任务返回排队提示。
- **可观测**:本地 trace 落盘 `outputs/traces/*.json`(Agent→Turn→LLM→Function span 链),
  默认的云端上传处理器关闭。

### 7.6 HTTP 契约(server.py,纯适配层)

| 方法 | 路径 | 说明 |

| POST | `/api/tasks` | body `{message}` → 返回 task_id(异步);模型未配置时 503 + 原因 |
| GET | `/api/tasks/{id}` | status / stage / narrative(LLM 叙事)/ error |

## 8. 前端契约(web/index.html)

单页静态页面,轮询任务状态;契约与 §7.6 一致:
自然语言输入 → 执行阶段展示(含 Agent 叙事与 MR 阶段)→ 五维前后对比(含"不适用"标注)→
处置统计(修复/去重/隔离/登记 + 代表性记录)→ 数据量变化 → T1/T2 与版本 → 局限说明 →
样例查看/报告下载 → 追问(展示回答与越界标记)。

## 9. 已知限制(如实声明)

1. 执行模式为容器内 local MapReduce,非 HDFS/YARN 多节点集群。
2. LLM 为外部服务依赖,可用性受 DeepSeek 服务质量影响;意图理解依赖模型能力,触发词
   注入门按中文关键词设计,英文等价表达需扩展词表。
3. M3/U 系"登记"类问题保留在数据中,清洗后仍有未解决字段(如实计数展示)。
4. 评分类指标无法证明数据"真实性",只能证明"值域/格式/引用合规"。
5. trace 未按 span 记录 token 用量(仅记录 span 结构与模型名),用量审计留给后续迭代。
