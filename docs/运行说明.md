# 运行说明(实测版)

本说明给出一条真实可复现的运行路径,所有数字均来自实际执行输出,不是估算。
Agent 层为 OpenAI Agents SDK + DeepSeek 的真实 LLM 循环,详见 §0 与
[Hadoop与Agent实现.md](Hadoop与Agent实现.md) §3。

## 0. Agent 架构

调用链(用户一次提示,自动完成清洗与评估):

```
用户自然语言
  → LLM(deepseek-chat)循环,决定调用哪个工具
    ├─ run_clean_data_pipeline   → pipeline.py → docker run → hadoop jar(12 次真实 MR 作业调用)
    └─ read_latest_report / read_report_field / read_registry / read_samples(纯读文件,秒回)
  → Agent 组织回答:状态、五维对比、数据量变化、处置区分、版本、T1/T2、局限
```

- 代码落位:`ml-1m/agent/loop.py` 为全部智能(LLM 循环、工具、会话记忆、防编造、trace、并发锁);
  `ml-1m/agent/server.py` 仅做 HTTP 适配(`parse_intent`/`answer_from_report` 手搓逻辑已删除)
- 模型:DeepSeek `deepseek-chat`,SDK 内置路径接入(`AsyncOpenAI(base_url="https://api.deepseek.com")`
  + `OpenAIChatCompletionsModel`);LLM 调用超时 120s,429/5xx 指数退避重试 2 次
- 需要密钥:复制 `ml-1m/agent/.env.example` 为 `ml-1m/agent/.env` 并填 `DEEPSEEK_API_KEY`
- 交互:发起任务异步(立即回 task_id,前端轮询含 agent 叙事与 MR 阶段);追问同步返回(2~5 秒)
- 会话记忆:SQLiteSession 落盘 `outputs/agent_memory.db`,按 task_id,服务重启后可继续追问
- 重跑门槛(结构强制):常驻工具仅只读组;`run_clean_data_pipeline` 只有当用户原话命中
  "重新/重跑/清洗/清理/再跑"类触发词时才注入本轮,其余场景模型想调也调不到
- 防编造:Prompt 三条硬约束(必调工具取数/修复≠删除措辞/未生成如实说)+
  回复后分数白名单校验(回复中的分数必须在 report 实测值集合内,越界附加标记)
- 并发:全局锁串行(管线共享 `_tmp_*` 临时目录),第二任务提示排队
- 可观测:本地 trace 落盘 `outputs/traces/*.json`,可查看 Agent 的完整推理链
- 配置预留:管线接受 `rule_pack` 档位参数,当前仅 `default`=rules-v2.0,未知档位显式报错

## 1. 环境要求

- Windows + Docker Desktop(Linux 容器)
- JDK 8(仅用于编译;安装目录用环境变量 `ML_JAVA_HOME` 指定)
- Python 3.10+(依赖见 `requirements.txt`:`fastapi`、`uvicorn`、`pydantic`、`openai-agents`)
- Docker 镜像 `movielens-hadoop:3.3.6`(构建脚本见 `runtime/`)
- 源数据:`ml-1m/data/users.dat`、`movies.dat`、`ratings.dat`(ISO-8859-1 编码)

> 从仓库克隆得到的工作区**不含**源数据与编译依赖 jar(许可与体积原因):源数据按 `README.md`
> 「获取原始数据」下载后放入 `data/`;`hadoop/build/deps/` 按 `README.md`「准备 Hadoop 依赖 jar」
> 从镜像中复制(清单 `hadoop/deps.manifest.txt` 为原构建实际使用的 125 个 jar,可用于核对)。

## 3. 运行步骤

### 3.1 编译 Hadoop 作业

```powershell
powershell -ExecutionPolicy Bypass -File ml-1m\run_iteration1.ps1 build
```

产物:`ml-1m\hadoop\build\iter1.jar`。

### 3.2 全管线(清洗+评分+报告)

```powershell
powershell -ExecutionPolicy Bypass -File ml-1m\run_iteration1.ps1 pipeline
```

等价于 `python ml-1m\pipeline\run_pipeline.py --tag iteration1-run`。

执行内容依次为:输入指纹 → 参照 ID 提取 → 原始评分(3 表)→ 用户清洗(U1–U6)→
电影清洗(M1–M7)→ 电影标题跨 ID 去重(M5b)→ 清洗后参照 ID → 评分清洗(R1–R9)→
清洗后评分 → 汇总报告。全部作业在 Docker 容器内以真实 Hadoop local MapReduce 执行。

产物:`outputs/<tag>/report.json`,并追加登记到 `outputs/registry.json`。

### 3.3 启动 Agent(含前端)

```powershell
powershell -ExecutionPolicy Bypass -File ml-1m\run_iteration1.ps1 serve
```

前置:在 `ml-1m/agent/.env` 填 `DEEPSEEK_API_KEY`(模板见 `.env.example`)。未配置 key 时
`POST /api/tasks` 返回 503 并明示原因,其余只读端点(报告/登记/前端)不受影响。

浏览器打开 <http://127.0.0.1:8000/>。

## 4. Agent API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/tasks` | body `{"message":"请清洗并评估 MovieLens 1M 的五个质量维度"}`;由 LLM Agent 理解并编排,含触发词(重新/清洗/清理)时注入执行工具,否则只读复用最新报告 |
| GET | `/api/tasks/{id}` | 任务状态 `running / success / failed` + Agent 叙事 `narrative`(LLM 生成)+ MR 阶段 `stage`;失败附失败环节与原因 |
| GET | `/api/tasks/{id}/report` | 完整评估报告(即 report.json) |
| GET | `/api/tasks/{id}/report/download` | 报告下载 |
| GET | `/api/tasks/{id}/sample` | 三表 clean/isolate/log 样例 |
| POST | `/api/tasks/{id}/ask` | 追问(同步):LLM 调只读工具取数回答;分数经白名单校验,越界在 `flagged` 中列出并附"未出自本次报告"标记 |
| GET | `/api/registry` | 版本登记列表(输入/输出数据版本、规则版本、T1/T2、切分计数) |

前端为三栏单页:
- **左栏 任务状态**:六步工作流(解析需求 → 准备数据 → 清洗前评分 → Hadoop 清洗 → 清洗后评分 → 生成报告),步骤状态由任务阶段(`stage`,来自持久队列与元数据)实时映射;当前任务卡(任务 ID/数据版本/规则版本/T1/T2/开始时间/运行时长);历史任务(来自 registry,可点击加载其报告)。
- **中栏 Agent 对话**:自然语言发起(含触发词时注入执行工具)、执行过程卡片镜像左侧步骤、完成后的 Agent 总结与继续追问;追问回答附"未出自本次报告"越界标记。
- **右栏 结果展示**:总览 / 五维评分 / 数据变化 / 问题处理 / 数据样例 / 评估报告 六个标签;柱状图对比清洗前后,Up-to-date 明确标注"不适用";问题处理按 修复/去重/隔离/登记/正常保留 分色卡展示(不提供"共处理 N 条"的合并口径);时间范围卡单独可见。

## 5. 实测结果(tag=iteration1-final,注册于 registry.json)

输入指纹:users/movies/ratings sha256 前 8 位见 `report.json.raw_sha8`。

### 5.1 数据量变化

| 表 | 原始行数 | 清洗后 | 处置量 |
| --- | --- | --- | --- |
| users | 6,946 | 6,112 | 834 |
| movies | 4,465 | 3,858 | 607 |
| ratings | 1,150,241 | 987,270 | 162,971 |

官方口径 1,000,209 条有效评分:本版本在 ID 去重(M5b)后进一步隔离了指向被归并
电影副本 ID 的评分(R9),因此有效行 987,270 少于不去重口径的 1,000,211(见局限 7)。

### 5.2 五维评分(原始 → 清洗后)

| 表 | Accurate | Complete | Unique | Up-to-date | Consistent |
| --- | --- | --- | --- | --- | --- |
| ratings | 90.09 → 100.00 | 99.23 → 100.00 | 89.31 → 100.00 | 96.32 → 100.00 | 92.43 → 100.00 |
| users | 90.31 → 99.75 | 99.22 → 100.00 | 89.55 → 100.00 | 不适用(静态快照) | 91.29 → 99.75 |
| movies | 91.94 → 100.00 | 98.47 → 100.00 | 92.18 → 100.00 | 不适用(静态快照) | 91.94 → 100.00 |

数据集综合分(ratings 0.6 / users 0.2 / movies 0.2 加权):**93.33 → 99.98**。

users 表准确率 99.75 非 100:U2–U5c 对无法核验的字段置 NULL 并保留在数据中,
评 value 域校验时 NULL 记为不合格(登记≠修复,见局限 4)。

### 5.3 时间边界与切分(登记后不可更改)

- T1 = 2002-01-01T00:00:00Z(train 截止,960,233 条)
- T2 = 2002-07-01T00:00:00Z(valid 截止,valid 14,391 条,test 12,646 条)

### 5.4 处置明细(计数来自 MR 输出聚合)

- users:U1a 截断修复 15、U1c 冒号行修复 25、U5a 邮编修复 66、U5b 修复 1、
  U2-U5c 登记保留 6,005、U1b 隔离 32;U6 去重日志若干。
- movies:两阶段合计。阶段一(id 级):M7/M8/M1 修复 3,859、M4 类型清洗 82、
  M2 隔离 128;阶段二(标题级 M5b):保留 3,858 行、归并重复 83 行。
- ratings:R1/R4/R6/R2/R8/R9 修复与隔离见 `report.json.disposition.ratings.counts`;
  R7 保留每 (user,movie) 最新一条。

## 6. 评价局限(报告内同步声明)

1. 执行模式为容器内 Hadoop local MapReduce(真实 MR 管线),非 HDFS/YARN 多节点集群。
2. Accurate 评的是值域合规+引用可解析,无法验证真实世界准确性。
3. users/movies 的 Up-to-date 不适用(静态快照无时间字段),不参与综合分。
4. 置 NULL/登记字段仍留在数据中,登记≠修复。
5. 隔离使分母变小,分数上升部分来自删除劣质记录而非修复。
6. 时间参照只覆盖 1990–2003;T1/T2 只用于切分,不参与打分。
7. M5b 标题归并后,指向被归并副本 ID 的评分按 R9 隔离;若业务优先保留评分量,
   可将 M5b 改为 ID 重映射并把评分改挂到保留 ID(后续改造方向)。

## 7. 已知边界

- 解析 agent 的意图路由是关键词规则,只覆盖清洗/评估类请求;复杂多步任务留给后续迭代。
- registry.json 为追加写,不做去重;同一输入重复运行会产生多条版本。
- `_tmp_*` 中间产物保留在 `outputs/` 下,便于人工抽验;可安全删除。
